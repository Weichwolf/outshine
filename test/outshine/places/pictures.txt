# THE PICTURES THIS TREE LAST MADE, and what each one cost.
#
# A line here is a SNAPSHOT in this tree's own grading: these bytes come out of one driver on one
# machine, so a digest proves AGREEMENT WITH OURSELVES and never correctness. Another GPU answers a
# different digest for the same correct picture. What it is FOR is a diff: a commit that was not
# supposed to move a picture and moves one says so here, in a line of text, instead of in a memory
# of what the last frame looked like.
#
# The picture itself stays OUT of the tree. `build/outshine-client shots` writes
# build/shots/<place>-<digest>.png, where a changed frame does not overwrite the frame it changed
# from and the two stand side by side for an eye. Committing the PNGs was considered and refused: a
# digest-named file is never overwritten, so six 720p frames a commit grow a repository
# monotonically with exactly the changes this engine is meant to make often.
#
# EVERY ONE OF THESE REPEATS. Ten consecutive runs of Central Park -- the worst of the six, which
# once answered three different pictures -- give one digest. A line that moves here is a change,
# never noise (board:2044).
#
# Rewritten by hand when a picture is MEANT to change. `make shots` prints the lines.
#

# Four of the six moved with board:2047 and the move is QUANTISATION, not a picture. The building
# mesher now emits an indexed mesh, so a corner reaches the device once instead of three times and
# the interpolator sums the same numbers in a different order. Measured against the frames they
# replace: OldTown 217 pixels of 921 600 differ, Heidelberg 84, Venice 258, Shibuya 220 -- and
# EVERY one of them differs by exactly 1 of 255. Central Park and the Jura did not move at all.

# ALL SIX MOVED AGAIN, and this time the move is NOT quantisation and is NOT yet defended. The
# subject's ambient now comes from the device's own sky integration instead of a CPU one, and the
# two DISAGREE: Shibuya's frame goes from a mean of 83.42 of 255 to 64.54, which is a factor of
# 1.71 in linear light over 582 910 pixels. Shibuya's rebuild falls from 907.8 ms to 107.0 in the
# same change, and the CPU integration -- 3 276 800 transmittance steps for one radiance -- is
# gone.
#
# WHICH OF THE TWO IS RIGHT IS UNSETTLED, and neither can settle it: both are ours, so agreement
# between them would prove agreement with ourselves and disagreement proves only that one is wrong.
# What can settle it is `ebruneton/clear-sky-models`, whose Kider et al. measurements are TRUTH
# grade, and board:2013 carries it. Until that runs, these six digests record WHAT THE TREE DRAWS
# and make no claim that it is right.
