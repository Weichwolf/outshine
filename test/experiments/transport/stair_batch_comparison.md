## Bounded execution

`stair_batch_experiment.py` keeps the old single-module experiment unchanged.
The new driver allows at most eight trials, eight sources per trial and 24 prior
modules, leaving eight slots in the existing 32-module chain. Each trial uses a
fresh process with the existing 120 CPU-second / 3 GiB address-space limits.
Defaults are 300 wall seconds overall and 60 wall seconds per isolated trial.
Initial prefix validation, termination and final report IO add explicit overhead;
this is not a frame deadline or a target-device budget.

Each successful trial must finish generation, the full saved-module reader and
fresh bound exports before extending the prefix. Recipe identities include the
complete canonical recipe; a refused recipe is not repeated in the same batch.
After success, selection runs against the new prefix. No persistent blacklist or
global maximality is implied. A new batch may reconsider previous refusals.

Timeout/nonzero exit retains the verified prefix and stops with its reason.
Zero exit without a complete fresh export is an error. An independent batch
reader reconstructs selection and every complete physical trial. It writes new
receipts using temporary hardlink input clones, preserving producer receipts.

The first installed run hit a real 60-second child deadline under concurrent
normal-priority vegetation rendering. It correctly retained 98 sources; step 4
had generated byte-equal geometry but had not finished verification and was not
promoted. Its fresh batch reader passed. After that competing render ended, a
fresh run with the same unchanged limits reached all 102 sources. All seven
artifacts of each of the five groups are byte equal to the source run.

their previous path. The transport consumer records an unbuildable remaining

part exactly once, either built or explicitly unbuilt. It rejects omitted,
duplicate, invented, geometrically changed or unexplained parts. Existing actual

## Equal-result cost comparison

Measured host: Linux x86-64, Intel i5-1135G7, four allowed logical CPUs. Producer:
CPython 3.13.5, NumPy 2.2.4, SciPy 1.18.1, Clarabel 0.11.1, Shapely 2.2.0 / GEOS
3.14.1. Actual consumer environment uses NumPy 2.5.4 and manifold3d 3.5.4.
Memray 1.20.0 records Python/native allocator requests without native call stacks.
Profiling processes have normal priority. This is a shared host, not an A18 Pro
or RTX 3060 device test; software-GL Workbench supplies the diagnostic images.

The alternative repeats the existing three-attempt, first-success experiment,
continuing its proposal offset after an all-refused window. It needs six calls
and thirteen physical trials to reproduce the same five groups. All 35 accepted
artifacts match, including on the separately profiled runs.

| Same five accepted groups | Existing serial calls | Isolated batch |
| --- | ---: | ---: |
| Physical trials | 13 | 8 |
| Recorded allocation requests | 248,233,501 | 240,908,564 |
| Cumulative requested bytes | 30,929,473,471 | 31,177,171,395 |
| Incremental traced heap peak, serial / largest worker | 45,781,501 B | 83,337,115 B |
| Separate batch parent traced heap peak | — | 24,886,175 B |
| Separate batch parent requested bytes | — | 228,835,986 B, included above |

The batch avoids five physical trials but cold worker imports, repeated selection
and cross-process acceptance checks consume the saving: 2.95% fewer requests,
0.80% more requested bytes and a larger worker peak. Keep isolation for its
explicit timeout/partial-result contract; this is **not a memory optimization**
and does not replace the existing generator or enter the reference library.
The two workflows include their actual selection, generation, saved readers,
hashes and exports. Common parent imports precede tracking; cold worker imports
are included because the isolated workflow requires them. The serial helper's
accepted-artifact equality hashes are included. Reported bytes sum independent
allocator requests, not copies, resident memory, held assets or transferred bytes.
Per-process heap peaks must not be added as an observed simultaneous peak.

The dominant recorded operations include GEOS union/difference/intersection,
coverage checks and old patch boundaries. The serial trace alone attributes
6.866 GB to `union_all`, 2.888 GB to geometry difference and 1.663 GB to coverage
validation. This costly Python proof/assembly path has no runtime cost approval.
Prepared immutable products and local work must replace repeated old-geometry
reconstruction before runtime integration. Do not infer speed from the unpaired
diagnostic wall times: source batch 78.35 s, serial 96.06 s; profiled 181.33 /
177.29 s. Copy traffic, parent RSS, simultaneous footprint and device times remain
unmeasured. Counts and byte identities establish work/quality, not frame fitness.
