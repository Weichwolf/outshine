# Native Vulkan adapter proof

Build the regular production archive first, then run its actual GPU consumers:

```sh
make all
python3 test/experiments/render/native_vulkan.py --validation --present \
  --device-name 'Intel(R) Iris(R) Xe Graphics (TGL GT2)' --output /tmp/outshine-vulkan-proof
```

`--present` requires SDL video and a working desktop connection. Without it,
only offscreen GPU contracts are checked. Private outputs stay in system temp.
The compute probe uses the production terrain scan followed by the test-only
`native_scatter.comp`: generic indexed copies exercise storage dependencies and
recorded resource lifetimes without retaining an alternative geometry renderer.
The runner links consumers against `build/liboutshine.a`, verifies selected
native archive members against CMake/Ninja inputs, and records source/archive hashes and the Git revision.
A dirty checkout is explicitly marked. Validation diagnostics fail the run.
`--device-name` must match the physical device name exactly; an unexpected device
fails the proof. Declare the corresponding name for another driver or GPU.
Validation enables synchronization checks through `VK_LAYER_VALIDATE_SYNC=1`.

The shared window consumer checks ordinary SDL windows, asynchronous acquisition,
actual image extents, draw/submit, foreign ownership/thread rejection, cancellation,
resize, hidden suspension/resumption, and destruction with a live lease. Window
resize is synchronized **only in test preparation** with `SDL_SyncWindow`:
`SDL_SetWindowSize` is an asynchronous request on X11, and pumping once need not
observe the new size. Existing stale-lease assertions remain mandatory.

The Vulkan-specific consumer checks driver backpressure, abandoned recordings,
a missing/cancelled matching lease, accepted submission across resize, and late
image/recording ownership after device shutdown. It renders an asymmetric X/Y
pattern into the actual acquired swapchain image, reads back every BGRA component,
and saves that exact image as `swapchain.ppm` for personal visual inspection.
Readback requires the surface's transfer-source capability; this device proof must
fail rather than skip missing support. No reference pixels are generated by the
renderer. The independent CPU formula allows one UNORM quantization step.

The initial window adapter requires Vulkan 1.3 and swapchain maintenance1. It uses
two queues in one graphics/compute/present family where available. A single queue
requires the advertised and enabled `VK_KHR_internally_synchronized_queues` feature;
its queue creation flag also accompanies `vkGetDeviceQueue2`. This path requires
headers declaring the extension and a validation layer that understands it.
Older headers retain the two-queue requirement. Ordinary SDL X11/Wayland windows
use SDL's native window properties; SDL Vulkan windows use its surface helper.
X11 is the measured platform; a compiled Wayland adapter is not a runtime proof.

SDR presentation prefers an actual sRGB attachment with SRGB_NONLINEAR surface
colourspace. The exposed image format determines pipeline selection; callers
must not assume BGRA UNORM. `CreatePresentPipeline` uses the existing copy shader
for sRGB targets and the explicit OETF variant for UNORM targets. The sampled
sRGB surface is already decoded to linear; hardware or shader encodes it once.
Alpha remains linear. HDR and data intermediates retain their original semantics.
The factory rejects non-SDR formats rather than applying another tonemap.

`NativeSdrTransferProbe` checks all 256 display code values and alpha on all four
RGBA/BGRA, sRGB/UNORM targets through the production pipeline factory. The original
unencoded UNORM copy is a mandatory negative control. Window probes derive their
CPU byte expectations from the actual target transfer and channel ordering;
offscreen UNORM expectations remain unchanged. The target-switch probe prepares
all supported SDR pipelines before SDL video, preserving its late-attachment
and original-resource lifetime checks. This is not a complete native Place proof.

The transfer contract is the existing
[SDL SDR_LINEAR contract](https://wiki.libsdl.org/SDL3/SDL_GPUSwapchainComposition)
and [Vulkan texel conversion](https://docs.vulkan.org/spec/latest/chapters/images.html),
confirmed for the migration in #328, comment 6200869285. Metal layer/display
colourspace and hardware image validation remain with its backend owner.
Headless operation does not require SDL initialization or presentation extensions.

A worker owns swapchain creation, finite-timeout acquire, present, and cancelled
image release. The caller only tries the bounded mailbox and records/submits to
the graphics queue. With one queue, Vulkan synchronizes concurrent host access
internally; Outshine adds no frame mutex around the worker's Present call.
There are three live lease slots and at most one
unsuccessful acquire attempt during a target change. Each lease owns two binary
semaphores and two fences; unsuccessful acquire retries reuse those objects.
The driver may expose fewer simultaneously acquirable images than the slot bound.
Each held lease keeps its swapchain generation and context alive. Retired targets
are removed once no image lease retains them. No GPU image allocation is copied
into a replacement image merely for presentation.
Each window also has an explicit Vulkan owner claim, shared by its live surfaces.
A competing device returns Busy before preparing a target, independently of the
driver's willingness to create multiple swapchains. SDL stores a weak claim;
retained surfaces keep ownership alive without querying SDL from their destruction
thread. The final surface releases ownership even after device facade shutdown.

Present transfers the lease into its recording. Submission waits for acquisition,
transitions the image to PRESENT, signals the render semaphore, and then publishes
the submitted lease to the worker. Cancellation waits for acquisition and all
recorded/GPU use before releasing the image. Present fences protect the lifetime
of presentation semaphores and old swapchains. GPU completion remains valid when
a later presentation or target generation fails. Unsubmitted old-generation
leases are Invalid. Shutdown joins the queue worker before device idle and then
drains present fences; frame operations never wait for the presentation queue.
Copyable swapchains disable clipping so advertised readback covers obscured pixels.

This is an adapter correctness proof, not a full native Stage/Client/Place proof.
It supplies no GPU stage timings, full-frame p99, total memory budget, A18 result,
or integrated Engine/SceneRenderer target switching. Those remain #243/#48/#188.
The backend target transaction is checked separately below.

`Device::SetPresentTarget(window)` prepares a target transaction outside open
unsubmitted recordings; those return Busy. Successful submissions may still be
pending. A failed preparation keeps the previous target and generation usable.
`nullptr` detaches to offscreen. Same-target selection is a no-op while healthy.
The optional presentation extensions and queue capability are prepared at device creation
without initializing SDL video. A device lacking that capability remains usable
offscreen and returns Unsupported for a later window. No device/world rebuild.

Surfaces own their context, swapchains own their surface, and leases capture an
immutable generation separately from the physical swapchain. The WSI worker can
therefore reuse a still-live inactive A swapchain after A→B→A without making old
A leases valid again. A driver-retired swapchain is not reused. Surface creation
and SDL property queries stay on the owner/main thread; swapchain preparation,
commit and later retirement stay on the existing worker. Only successful
preparation publishes the new target. The synchronous target-preparation call
may wait outside frames; Acquire continues to try the ready mailbox.

The additional `NativePresentTargetProbe` creates its device, pipelines, texture
and GPU buffer before SDL video, then checks late attachment, different window
extents, A→B→A stale rejection, Busy with an open recording, offscreen raster and
readback on the original texture, pending GPU work across detach, occupied-window
rollback and wrong-thread rejection. Its long integer kernel is a test workload,
not renderer work. Host target-call/Acquire maxima are diagnostic observations,
not frame p99 or GPU time. Window pixel readback is checked only if CopySource is
advertised; offscreen readback remains mandatory.

For an actually non-present-capable Vulkan driver, run the same compiled consumer
with `--unavailable`, optionally selecting that driver via `VK_DRIVER_FILES`.
It requires Unsupported for window attachment and verifies the pre-existing
buffer/queue remain functional. This does not replace the actual target-device run.

`DeviceOptions.GpuTiming` selects `GpuTimingMode::None`, `Submission`, or `Dispatches`.
None is the default and creates no query pools, timestamp commands, result reads,
or completed timing history. Submission records the whole command buffer; Dispatches
also records bounded per-dispatch intervals. SceneRenderer and calibration select
Submission; dispatch probes select Dispatches. `Capabilities.GpuTimestamps` reports
hardware timestamp support separately. A requested mode without backend support
returns Unsupported at device creation. Metal supports None and Submission and
explicitly rejects Dispatches; whole-command-buffer time is not a substitute.

`GpuTimings(Completion)` never waits for the GPU. Pending results contain no
dispatch samples. Ready results include the actual DispatchCount and at most
128 samples in recording order. Truncated explicitly reports further dispatches.
Only the last eight completed submissions retain results, including submissions
without dispatches. Expired, foreign and invalid completions return Invalid;
disabled or unsupported timing returns Unsupported. Retrieval is repeatable and
returns an independent value. Device access remains on its owner thread.

Each sample supplies its ordinal, raw Begin/End, NanosecondsPerTick, ValidBits
and Available. Unavailable samples have zero raw values and must not be used
as zero elapsed time. For an available sample, mask unsigned `(End - Begin)` to
ValidBits before multiplication by NanosecondsPerTick; 64 bits uses UINT64_MAX.
The interval must be shorter than the counter wrap period. There is no calibrated
CPU timestamp, cross-device clock or GPU core-frequency claim.
The host interval from recording to completed query retrieval bounds the possible
GPU duration. A counter delta outside that bound or an interval long enough for
multiple wraps is unavailable. This rejects provably disjoint values; Vulkan has
no separate disjoint flag, so undetectable driver clock faults are not claimed.

Vulkan resets a bounded query pool in its recording, writes TOP_OF_PIPE after
resource barriers and pipeline/binding recording immediately before Dispatch,
and writes BOTTOM_OF_PIPE immediately after Dispatch. This is a GPU execution
enclosure and may include dependency stalls. These per-dispatch intervals exclude
other upload/readback commands, queue/fence wall time and host result retrieval. Completed query results are read
without WAIT before recording resources are destroyed; pool destruction follows
the same GPU lifetime as the command buffer. The source technique is the
[Khronos timestamp example](https://docs.vulkan.org/guide/latest/profiling.html).

`NativeTimingProbe` checks real Pending/Ready, dependent arithmetic/readback,
per-dispatch availability and metadata, truncation, eight-submission retention,
independent repeated retrieval, owner rejection, abandoned recordings and
shutdown with accepted GPU work. These checks establish the timing contract,
not a full renderer, image-quality improvement or target-device frame budget.

`ReadbackTransfer` is the native readback state used by the renderer migration.
Start submits a copy of an image region or buffer byte range. Poll only asks for
completion and exposes no partial bytes; Wait accepts an explicit finite caller
budget for offline capture. The transfer owns the destination buffer and its
mapped allocation, not a borrowed Device pointer. Each query requires the correct
live device/owner, even after mapping. A returned span remains valid while its
transfer owns the allocation, including across transfer moves and after device
facade destruction. Native resource ownership retains accepted copies when their
source wrapper or an abandoned transfer is released. Image bytes are packed by
row without format conversion; RowBytes describes that packing.

The real GPU probe verifies mip/array-layer crops, partial buffer ranges,
nonblocking pending data, move/lifetime behavior, cancellation, wrong owner and
overflow/bounds rejection. It does not establish completion of the SceneRenderer
port: the existing SDL readback is removed when its actual callers migrate under
#328. There is no fallback from native failure to SDL.


`NativeDescriptorProbe` exceeds the former single-pool limit with independently
checked compute words and raster pixels. It changes a buffer between repeated
bindings, overwrites caller uniform payloads after recording, and releases public
resources before completion. Cancellation, rejected submissions, completed
lifetime, and a capacity failure followed by submission of the valid prefix are
separate cases. The validation runner treats every diagnostic as a failure.

Each recording reuses resolved descriptor sets, immutable uniform snapshots and
image views. Uniform data occupies aligned 64 KiB pages; the original small
128-set pools grow only after allocation exhaustion. Recording ceilings are
16,384 sets, 128 pools, 16 MiB uniform capacity and 16,384 views. These independent
logical ceilings are not a complete host/driver memory budget. Resources and
pools remain owned until that recording's actual completion or cancellation.
Every repeated binding still validates resources and records their barriers.

The fixed `test/outshine/data/render/husum-shadow-bindings.json` captures the
original failing public Husum recording, preserving uniform bytes and consistently
normalizing opaque resource identities. `descriptor_work.py` compares fresh,
whole-binding and per-set allocation work on equal trace prefixes. Its output
separates the requested prefix including the rejected final request from the
accepted prefix; it does not estimate device time or driver allocations. The
runner saves this comparison as `descriptor-work.json` beside the GPU log.
The techniques follow SIGGRAPH 2015's GPU-driven rendering discussion and
[Khronos descriptor management](https://docs.vulkan.org/samples/latest/samples/performance/descriptor_management/README.html);
measured Outshine costs and the exact scope remain in #398.


`SubmissionGpuTime(Completion)` implements the shared Metal/Vulkan contract. Vulkan
uses two query slots in Submission mode and two submission slots plus 256 dispatch
slots in Dispatches mode. A TOP_OF_PIPE marker starts the complete recording;
BOTTOM_OF_PIPE follows its final work,
including raster, copies and presentation transitions. Results are collected
without WAIT_BIT only after the actual submission fence completes. Pending
returns no invented elapsed time. Invalid/unavailable timestamps return an
explicit error; disabled timing returns Unsupported. The retained eight results
own numeric metadata rather than command buffers, query pools or GPU resources.

This same-queue GPU interval is separate from CPU encode/submit/fence waiting,
dispatch sums and display presentation. It may include GPU dependency stalls;
markers and optional per-dispatch instrumentation also have measurement cost.
Submission mode resets two slots, writes two markers, and reads two completed
queries per recording. Dispatches mode resets 258 slots and additionally writes
two markers per measured dispatch; None performs no query work. No claim is made
about driver allocation bytes or active GPU cycles. The shared
`NativeSubmissionTimingProbe` verifies explicit modes, submission measurements,
ownership and retention; the Vulkan scope probe additionally verifies pure
copy/raster submissions, cancelled recordings, resource retirement and
byte-identical timed/untimed raster output.
Its `submission-scope.ppm` contains the actual checked GPU pixels. See #411 and
the [Khronos timestamp sample](https://docs.vulkan.org/samples/latest/samples/api/timestamp_queries/README.html).
