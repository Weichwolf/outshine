## Goals
- Lean, fast, robust C: small static binary, minimal dependencies (libcurl, stb, pthreads), no
  frameworks. Hot paths cache-friendly and measured; cold paths simple and obvious.
- The origin serves cache misses only — nginx (same container, `proxy_cache`, versioned immutable
  URLs) and client caches absorb the traffic. Optimize bake latency and parallel throughput, not
  connection handling; TLS/HTTP2/C10K belong to the proxy layer.

## Conventions
- Concurrency: all endpoints run on the worker pool. New state is thread-safe by construction —
  atomics for counters, per-key inflight dedup for generated artifacts (one bake, N waiters), no
  function-scope statics in raster/encode paths, tmp-file names carry the thread id before rename.
- Determinism: identical requests yield byte-identical responses (md5-stable), across threads,
  restarts and rebuilds. Hash-seeded sampling instead of rand().
- Versioning: any change to generated bytes bumps `FB_OSM_STYLE_VER` — disk filenames and client
  URLs move together (immutable-cache contract). One bump per content change, no bundling of
  separately reviewable changes under one version.
- Blocking semantics: generation endpoints block until the artifact is ready; the client's timeout
  is the only deadline.
- Measurement before/after for every performance-relevant change: cold-bake timings per tex level
  on a fixed reference tile (alternating runs against the previous binary), byte sizes, `/health`
  counters. A change ships with its table.
- Robustness proofs per change: parallel race stress (N tiles × M concurrent requests), inflight
  dedup evidence (exactly one generation), `/health` clean (`bake_fail=0`, `scanline_refused=0`,
  `style_unknown_kind=0`).
- Build clean under `-Wall -Wextra -Werror`. Deploy = container rebuild + restart on the shared
  cache volume; verify through the real deployed stack (nginx port), including an `X-Cache-Status`
  HIT on repeat.
