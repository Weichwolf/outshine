**Refusal — and most of it is not a run-time refusal at all**

- [x] With a `constexpr` catalogue, **a stage reading a resource nothing produces, a cycle, a two-writer resource and an output with no producer are properties of the catalogue** and are held by `static_assert`, not by an error string: they are engine defects, and an engine defect that compiles is a defect the consumer gets blamed for. Six of them (`render/plan/RenderCatalogue.h:345-362`): every row at its own index · every read has a producer · one writer per derived resource · every attachment has a contributor · the enumeration is a linear extension · every declared fusion is adjacent and fed
- [x] The run-time refusals are exactly the consumer's own four, each naming the **declaration path** in the established `Fields` style (`scenario/Fields.h:1-8`) — an unknown stage name · a content stage that can contribute to nothing the plan requests · an attachment with **zero** contributors · an option no stage in the compiled plan reads (`render/plan/RenderPlan.cpp:134-198`; all four in `test/outshine/unit/render/plan/APlanIsPulledFromWhatItRequests.cpp`)
- [x] **The zero-contributor rule is the anti-vacuous rule and it is named as such**: a plan that compiles, runs and renders black is *the vacuous gate wearing a pipeline*, and it is refused at declaration rather than discovered in a PNG (`render/plan/RenderPlan.cpp:92-97`; `test/outshine/unit/render/plan/APlanIsPulledFromWhatItRequests.cpp` — *"a picture with no content stage at all is refused rather than rendered black"*)
- [ ] **The option check is `Fields::Closed()` for the render block** — an option nothing reads is refused with its path. This is the mechanism that already stopped eighty dead fields surviving across ten scenes (the bug tasks in `board/`), applied before the render declaration can grow its own eighty. *The two options that exist are checked (`render/plan/RenderPlan.cpp:186-198`); the render block itself has no reader yet — nothing under `src/scenario/` or `src/clients/` compiles a plan, and the sole `Renderer::Init` caller is `test/shared/render/Parity.cpp:516`*
- [x] **The refusal names the repair, not only the defect**: the resource that was missing, the stage that reads it, and — when the catalogue holds one — the stage that would have supplied it. The catalogue is `constexpr`, so naming the supplier costs nothing at run time (`render/plan/RenderPlan.cpp:44-56`; `test/outshine/unit/render/plan/APlanIsPulledFromWhatItRequests.cpp` — a lit surface with no shadow map is told `declare render.content.shadowMap`)
- [x] **No `throw`, no `std::optional`, no bare `bool`**: `[[nodiscard]] bool Compile(const PlanSpec &, RenderPlan *out, std::string &err)`, and on `false` the out-parameter is untouched — the shape the bug tasks in `board/` derived for this tree, where the value that says *no* carries no spendable payload (`render/plan/RenderPlan.h:64-65`; the out-parameter is `std::shared_ptr<const RenderPlan> *`, because the plan is immutable and outlives the compile — `R.21`'s exception, sharing is what a plan is for; `test/outshine/unit/render/plan/APlanIsPulledFromWhatItRequests.cpp` — *"the refused plan left the handle untouched"*)
- [x] **`RenderPlan` has no public constructor**: it exists only as `Compile`'s output, so *a renderer holding an unvalidated plan* has no spelling. The model is already in the tree — `generators/GroundPatch.cpp:19-20`, private constructor, `Complete` refusing unless every posting resolved (`C.41`, `C.42`). `render/plan/RenderPlan.h:102-103`
