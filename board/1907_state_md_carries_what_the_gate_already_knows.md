# STATE.md carries every measurement the gate already makes, and no line it did not measure

`STATE.md` is CURRENT for the developer and the review both, generated by `test/run.sh --state`
on every `make`. It is deterministic -- rebuilt at a32c4919 in a second worktree it comes back
byte-identical -- and that is what makes it worth reading first. Four defects stand in it.

**1. The PROVES walk swallows prose that is not a claim.** The extractor starts accumulating at
any line matching `Covers\(` and stops at the next `);` (test/run.sh, the STATE block). A source
that NAMES `Covers("` in a comment therefore contributes comment text:

    STATE.md, first PROVES line:
      , while every source that // does not is bound. Nine live citations stood under tools/ ...
    test/harness/claims/TheSourceCarriesNoCommentary.cpp:165

The one page that cannot be edited into a lie carries a line the tree does not prove. The walk
must anchor on a claim's own syntax, not on the four characters `Covers(`.

**2. It counts 49 public data members and names none of them.** `--audit-access` computes
`OPENDATA=49` and refuses when it moves; the ACCESS section prints only the six `protected:`
files. Half the measurement reaches the page. The same walk that lists the six lists the 49.

**3. It does not carry the standing reds.** `EXPECT_FAIL` declares 74 cases whose red is a
finding rather than a licence, 39 of them `khronos/validator`. Nothing on the page says so, so
"what is red today" is the one question STATE.md cannot answer.

**4. It does not measure the door rule, which is the tree's loudest standing violation.**
`LayerIncludes` (test/run.sh:210-224) grants 13 of the 17 declared suites a `-Isrc/...` path;
only `harness/wpt/css`, `harness/test262/js`, `apps/driver/src` and `apps/viewer/src` reach the
library through `include/` alone. CLAUDE.md says everything under `test/` reaches the library
through `include/` and NOTHING of `src/` (board:1879). The number is one `grep -c` away from the
table that grants it.

**5. The shape it draws, and the tier audit beside it, resolve an include by BASENAME.** Both
walks do `sed 's|.*/||'` and look the basename up in one table, so two headers with the same name
in different modules would be attributed to whichever the table listed first -- a tier crossing
would go unseen and an edge would be drawn to the wrong module. `TWINS` reports `none` today, and
that is the only reason the walk is sound; nothing REFUSES the day a twin appears.

## What will be true

- [ ] Every PROVES line is a claim a case makes, and a comment naming `Covers(` contributes none.
- [ ] ACCESS names the 49 public data members by file, as it names the six protected sections.
- [ ] A REDS section lists what `EXPECT_FAIL` declares, with its count.
- [ ] A DOOR section states how many declared suites reach past `include/` into `src/`, and which.
- [ ] A colliding header basename refuses in `--audit-layers`, because both walks depend on there
      being none.
- [ ] Proving case: a claims case seeds a comment carrying `Covers("` into a test source and the
      generated page is unchanged. Negative control: the same seed against today's walk changes it.
